# willitharness: Lean 4 proofs (contract v0.3)

Proves the logic layer of `docs/contract.md` (v0.3). It does not prove the numeric code or any agent behavior. See "Not proven".

## Toolchain (measured)
- Lean 4.36.0 (commit 611c117bfaf7b7ae1cfcf246ce6fba31e8f509e9, arm64-apple-darwin24.6.0).
- Lake 5.0.0. elan 4.2.4.
- Installed under `~/.cache/willitharness/elan` (set `WILLITHARNESS_ELAN_HOME` to use another folder). No Mathlib. Core Lean only.
- Pinned: `check_lean.py` compares the sha256 of `lean` and `lake` with `PINNED_BINARY_SHA256` (macOS arm64 only) before it runs anything. The pins equal the binaries inside the official `lean-4.36.0-darwin_aarch64.tar.zst` release archive (archive sha256 `49acada8749ad1343eff1224a3d2510ac61ed53363d37b5e738e8c587e7deabd`, checked against GitHub on 2026-11-18). Other platforms fail with "no pin" until their digests are added. elan itself is not pinned.

## S2 is a type-level argument, not a deep theorem
`decideRule : Reach -> EffectResult -> GuardResult -> Decision` has no parameter that
could carry side-effect data. `decisionWithReport` takes a `SideEffectReport` and
ignores it, and `S2_side_effects_never_change_decision` proves that by `rfl`. The
theorem documents the design. It does not detect a future change that makes the
real pipeline read side effects. That needs a test on the implementation.

## Assumptions (class fields, not `axiom` declarations)
1. `DiffOracle.diff_ordered` (contract DI-1): low <= high.
2. `DiffOracle.diff_swap` (contract DI-2): diff b a = (-high, -low) of diff a b.
3. `WilsonOracle.wilson_bounds` (contract V5): bounds for valid counts. Only the
   restatement `V5_interval_bounds` uses it.
The old `diff_self` field is gone. It is now the theorem `diffSelf_derived`, proven
from DI-1 and DI-2. A witness (`zeroOracle`) shows DI-1 and DI-2 are consistent. No
witness exists for `wilson_bounds`.

`#print axioms` shows only Lean's standard axioms for all 95 theorems.
`check_lean.py` regenerates `Audit.lean` from every `theorem` it finds, so a new
theorem cannot skip the audit.

## Not proven
- The numeric Wilson and Newcombe code, and that it satisfies DI-1, DI-2, V5. Only
  property tests can cover that.
- Agent behavior, shell command parsing, the `claude` CLI, hooks, permissions.
- The TLA+ lifecycle (L1 to L6, L9, T1, T2, T2a). Another fork owns it. The Lean
  `Reported` predicate models L7, L8 and P4 as pure gates. `reported_table.json`
  (54 rows, `canReport`) gives the implementation a golden table for it. Nothing
  machine-checks that it agrees with the TLA+ version.
- Warnings (W-LOWN, W-DENIAL, `saturated`, `pooled`) and "report only, never change
  a verdict". Only S2 is modeled, and only by type.
- How coverage, `bypassRate` and the usable-run counts are measured. Lean takes
  them as inputs.
- Report text (for example the D6 wording).

## Golden table conventions
- `decision_table.json`: reach x effect x guard, 3 x 5 x 3 = 45 rows. Unchanged from v0.1.
- `effect_table.json`: noise (NoiseUnmeasured, NoiseFloorTooHigh, NoiseOk) x verdict
  (InconclusiveSmallN, FirstHigher, FirstLower, Inconclusive) = 12 rows.
- `probe_table.json`: runs 0 to 6, targetHits 0 to runs, controlHits 0 to runs,
  so 1 + 4 + 9 + 16 + 25 + 36 + 49 = 140 rows.
- `guard_table.json`: completed in {NoGuardArm, InconclusiveSmallN, FirstHigher,
  FirstLower, Inconclusive} x coverage (Full, Partial, NoneSeen) x bypassRateZero
  (false, true) = 30 rows. Row shape: `completed`, `coverage`, `bypassRateZero`,
  `guard`. `NoGuardArm`, `InconclusiveSmallN` and `NoneSeen` each give GuardUntested.
- `arms_table.json`: promptVsComponent (4 verdicts) x nothingVsComponent (4 verdicts) x
  nothingClean (false, true) = 32 rows. Row shape: `promptVsComponent`,
  `nothingVsComponent`, `nothingClean`, `verdict`.
- `reported_table.json`: hasNoisePair (false, true) x noise (3) x looProbe (3) x
  ruleReach (3) = 54 rows. Row shape: `hasNoisePair`, `noise`, `looProbe`,
  `ruleReach`, `canReport`.
Rows are in a stable order: the order of the lists in the Lean source.
